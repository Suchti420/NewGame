## 1. Befund: Ist es zeitgemäß 2026?

**Technisch: nein. Konzeptuell: ja, mit Korrekturen.**

### 1a. Konzept-Check (Marktstand Oktober 2026)

Die Gesamtkombination existiert nicht. Aber jedes Einzelbaustein ist besetzt:

| Baustein | Nächster Nachbar | Abstand |
|---|---|---|
| Fragile Carry | R.E.P.O. (266.908 CCU Peak), Lethal Company, Heist of Fools (2027) | immer an Monster/Wächter/Timer gekoppelt |
| Cozy + Extraction | Escape from Duckov (3 Mio. Verkäufe in 3 Wochen), Solarpunk (1,2 Mio. Wishlists), Outbound | Duckov hat Combat; Cozy hat keine Extraktions-Spannung |
| Rucksack-Tetris | Backpack Battles + ~9 Nachbauten (Backpack Dungeon, Outpacked, BARDA, Turnbound), Sort-Puzzle auf Mobile: **477,6 Mio. $ (+170 %)** | aber 2.000+ Block-Puzzle-Launches in H1 2026 — der Markt ist geflutet |
| Daily-Seed | 789 Daily-Games, Blue Prince, Balatro | Daily-Seed als **Hauptschleife** in Spielen kaum besetzt |

**Der echte White Space:** „Fragile Carry **ohne jeden Antagonisten**". In jedem Nachbar-Titel ist Zerbrechlichkeit an Monster, Wächter oder einen bösen Timer gekoppelt. Ein unabhängiges Design-Dokument nennt das „strong white space"; ein Reddit-Thread vom 11.02.2026 („Cozy extraction game like REPO without horror") zeigt Nachfrage ohne Angebot.

**Marktkontext Mobile:** Game-Downloads H1 2026 **−12 %**, Mid-Core −7 %. Nur Hybrid-Casual wächst (+23 %) — und das bedeutet Meta-Progression/Booster/IAP, also genau **nicht** unser Ansatz. Konsequenz: **Mobile-Konsumgüter-Monetarisierung ist für dieses Konzept tot. Privatnutzung ist genau die richtige Zielgruppe.** Der Nutzer hat das mit „nur für meinen privaten Gebrauch" bereits richtig entschieden.

### 1b. Kritische Designfehler (nicht nur Codefehler)

| # | Befund | Fix |
|---|---|---|
| D1 | **Die Kernmechanik existiert nicht.** `comboScore` (Z.291) vergleicht **Objektidentität**, nicht Farbe. Nachgerechnet: über alle Positionen × Rotationen ist der Bonus **konstant** (O=40, I=20, L/T/S=30, dot=0, P=50). Der Spieler kann den Wert nicht beeinflussen. Zusätzlich: alle 8 Farben sind eindeutig, Farbgleichheit ist unmöglich, ein `x2`-Multiplikator existiert im Code nicht. | Cluster-Scoring per Flood-Fill über Farb-**familien** + echter Multiplikator |
| D2 | **11,8 % der Tage sind unspielbar.** Der Portal-Schutz (Z.154) testet die Wand-*Ecke* statt des Rechtecks gegen den Schutzkreis; Spawn (400,330) liegt 80 px unter dem Portal. Über 3000 Seeds nachgerechnet: 13,6 % Spawn-in-Wand, **11,8 % harter 180-s-Lock**. `collide()` prüft nur, es löst nicht auf. | Invariante per Konstruktion: Flood-Grid-Beweis, deterministischer Salt-Bump |
| D3 | **„Langsam = sicher" ist falsch.** Die Schadensschwelle `impact>2.2` (Z.340) liegt **unter** der Gehgeschwindigkeit 2.6 → Gehen verursacht bereits Schaden. Ohne Cooldown stirbt ein Echo in **3 Frames (0,05 s)**. | Schaden aus echter Relativgeschwindigkeit, Schwelle **über** Gehgeschwindigkeit, 450-ms-Cooldown |
| D4 | **Score ist framerate-abhängig.** `dt` (Z.323) wird berechnet und nie benutzt. 144 Hz = **4,8× so schnell** wie 30 Hz; Sprintschaden 972 %/Tag statt 216 %. Für ein zeitbasiertes Daily mit Highscore ist das ein Fatalfehler. | Fixed-Timestep-Accumulator (120 Hz) + gerenderte Interpolation |
| D5 | **Diagonale ist 1,41× zu schnell** und verursacht **41 % mehr Schaden** bei identischer Absicht (Vektor nicht normiert, Z.332–339). | `normalize()` des Eingabevektors |
| D6 | **Zeit läuft im Intro ab.** `startT=Date.now()` beim Parsen (Z.322), Startbutton (Z.317) viel später. Auch `toggleHelp` pausiert nur `running`, nicht die Zeit. | Zeit als akkumuliertes `dt`, Pausen frieren sie ein |
| D7 | **Zeitbudget umgehbar.** `toggleBackpack` prüft Portal-Nähe nur beim Öffnen (Z.249), `bpConfirm` gar nicht (Z.297). Spieler: `Q` → Rucksack auf → weglaufen → „Extrahieren" → Score gutgeschrieben. Und Extraktion ist **nach `endDay()`** möglich. | Eine Zustandsmaschine, Portal-Nähe pro Tick |
| D8 | **Racksack-Puzzle hat keinen Druck.** 30 Zellen, Carry-Max 3, größte Form 5 Zellen → **max. 15 belegte Zellen**. Jedes Teil passt immer. Und: eingepackt = immun gegen Schaden → **Anreiz ist invers** (sofort einpacken ist immer optimal). | Grid 4×4, Carry 5, Timer läuft beim Packen weiter |
| D9 | **Seed-Determinismus gebrochen.** `Math.random()` an 3 Stellen (Z.229, 352, 359/360). Das Spiel verspricht „gleiche Karte für alle heute", der Integritätsverlauf ist aber nicht reproduzierbar. | Eine PRNG-Instanz pro Runde, `Math.random()` verboten |
| D10 | **UTC-Seed.** `toISOString()` → Seed wechselt 22:00–00:00 lokal. | Lokales Datum + Versionssalt im Seed |
| D11 | **Kollisionsgrenzen widersprüchlich.** Clamp 20 (Z.350) vs. Kollision `r+14`=26 (Z.217) → 4 tote Randbereiche. Drop (Z.229) ohne Kollisionsprüfung, Pickup-Radius 44 statt 23 → **Aufnehmen durch Wände**. | Eine Wahrheit für Grenzen; Radius = r1+r2; Sichtlinienprüfung |
| D12 | **Dokumentation lügt.** „Sprint + Wand = −25 %" (real: 22 % *pro Frame* beim Gehen). „x2 Combo" (existiert nicht). | Regeln aus `config.ts` generieren, Text aus derselben Quelle rendern |

## 2. Systemvergleich 2026 — was gibt es, was nehmen wir

### 2a. Rendering-Backends (Android)

| System | Stärken | Schwächen | Urteil |
|---|---|---|---|
| **Canvas2D** | Immer verfügbar, kein Context-Loss, 0 KB Dependency, exakte Text-/Form-Rendering-API | `shadowBlur` = eigener Blur-Pass **pro Draw-Call** (Chromium 3,4 ms/400 draws); pro-Frame-Allokation erzeugt GC-Pausen | ✅ **Basis** — bei ≤15 Entitäten völlig ausreichend |
| **WebGL / PixiJS 8** (8.20.0) | GPU-beschleunigt; Bunnymark: 100k bewegte Sprites ~2 ms statt ~15 ms CPU | PixiJS hat den WebGPU-Renderer in **8.1.0 bewusst auf WebGL zurückgestellt** (WebGL ist bei Texture-Uploads schneller). WebGL-Context-Loss auf Android, Shader-Compile-Hitches | ❌ Overkill für 15 Sprites; 345 KB–1,3 MB |
| **WebGPU** | Modernste Pipeline | **Auf Android praktisch unbrauchbar**: Chrome 121+ **und** Android 12+ **und** Qualcomm/ARM. **Firefox Android fehlt komplett.** **Samsung Exynos laut gpuweb-Wiki „TBD"** — und Exynos ist sehr verbreitet | ❌❌ Ausgeschlossen |
| **Phaser 4.2.1** | Vollständig, Arcade-Physics, 345 KB gzip | Overhead ohne Nutzen bei 15 Entitäten | ❌ |
| **Godot 4.7 Web** | Volle Engine | **33 MB wasm / ~12 MB gzip**, Single-Threaded-Default, `SharedArrayBuffer` braucht COOP/COEP-Header — blockiert PWAs, `credentialless` fehlt in Safari/Firefox-Android | ❌❌ Selbstbestrafung |
| **Unity 6 Web** | Verbreitet | 3–8 MB brotli, WASM-Compile-Overhead, Multi-Prozess-Browser | ❌ |
| **Kaboom.js** | Winzig | **Archiviert.** Nachfolger KAPLAY ohne Institution | ❌ |

**Konkrete Canvas2D-Budgets (gemessen, Chromium):** `shadowBlur`-Draw-Calls **≈ 50–100 pro Frame** als Obergrenze für Midrange-GPUs. Neu erzeugte Gradienten **≤ ~1 pro Entität/Frame**, besser gecacht. Keine Per-Frame-Allokation im Renderloop. `willReadFrequently: true` **nie** setzen (schaltet GPU-Beschleunigung ab, gemessene Commit-Zeit stieg auf 47 ms).

### 2b. Distributions-/Container-Systeme (Android)

| System | APK-Größe | Engine | Offline | Secure Context | Ohne Play Store | Urteil |
|---|---|---|---|---|---|---|
| **PWA (WebAPK)** | cloud-gemintet | Geräte-Chrome | via SW | ✅ | ✅ | ⚠️ Heuristik: `beforeinstallprompt` braucht **1 Tap + 30 s**. `file://` ist **tot** (Chromium whitelistet nur localhost) |
| **Bubblewrap / TWA** | 0,8–5 MB | Geräte-Chrome (Custom Tab) | via SW | ✅ | ✅ | ❌ Braucht zwingend `assetlinks.json` auf kontrollierter HTTPS-Origin → disqualifiziert für „ohne Server" |
| **Capacitor 8.5.0** | ~4 MB | Android System WebView | **garantiert** (lokal) | ✅ `https://localhost` | ✅ | ⚠️ Korrekt, aber npm-Dependency-Tree + Plugin-Oberfläche für **eine** WebView |
| **Hand-gebauter Gradle-Wrapper + `WebViewAssetLoader`** | **~0,3 MB** | Android System WebView | **garantiert** | ✅ `https://appassets.androidplatform.net` | ✅ | ✅ **Gewinner** |

**Der entscheidende Punkt:** Nur die WebView-Varianten laden Assets **lokal aus dem APK**. `WebViewAssetLoader` (androidx.webkit 1.17.1) liefert sie unter `https://appassets.androidplatform.net/` aus — das ist ein **echter Secure Context** mit eigenem Origin, also funktionieren IndexedDB, `storage.persist()`, WakeLock, Fullscreen und Orientation-Lock. Und: die Daten liegen im **privaten WebView-Datenverzeichnis der App**, nicht im Chrome-Profil — „überlebt Browser-Daten-Clear" ist erfüllt. Ohne Capacitor: 0 npm-Dependencies, keine Plugin-Versionen, kein Update-Pfad-Drama.

**Warum Java statt Kotlin:** eine einzige Activity, ~150 Zeilen. Kotlin würde eine zusätzliche Gradle-Plugin-Auflösung über den Plugin-Portal erfordern — zusätzliche Build-Risiken ohne Nutzen. Java 17 + AGP 8.13.2 + Gradle 8.14 ist eine rocksolde Kombination (Java 17 ist installiert, Gradle 9.8.1 auch, AGP bis 9.4.1 auf Google Maven erreichbar, `android-36` installiert).

### 2c. Storage-Systeme

| System | Überlebt App-Kill | Überlebt Daten-Clear | Limit | Urteil |
|---|---|---|---|---|
| `localStorage` | ✅ | ❌ | 5 MiB, **synchron**, blockiert Main-Thread | Nur Settings-Flags < 50 KB |
| **IndexedDB** | ✅ | ❌ | 60 % der Disk | ✅ **Spielstand** |
| OPFS | ✅ | ❌ | 60 % der Disk | Overkill |
| **Native App-Datenverzeichnis** (WebView-Origin) | ✅ | ✅ | App-Speicher | ✅ **Rahmen** |

**IndexedDB-Detail das den Unterschied macht:** Chrome hat den Default von `strict` auf **`relaxed`** umgestellt (Chrome 121) — `complete` feuert, sobald Daten an den **OS-Puffer** gingen. Perfektgewinn laut Chrome: 3–30× schneller, aber **Powerloss in den folgenden Sekunden kann die Transaktion verlieren**. Für den Spielstand ist er die einzige Kopie → also **`durability: 'strict'` explizit setzen** (Aufwand vernachlässigbar). Und `tx.commit()` statt auf `onsuccess` warten — genau dafür wurde es entworfen (Chrome 76), ideal für `visibilitychange`/`freeze`-Handler.

**Nie `beforeunload`/`unload` für Persistenz** — auf Mobile feuert das praktisch nie, und Chrome hat es **ab 22.09.2026 auf 100 % der Page-Loads** umgestellt.

### 2d. Android-Lifecycle — was tatsächlich zuverlässig ist

```
active → passive → hidden → frozen → discarded
```

- **`visibilitychange` → `hidden`** ist der **letzte zuverlässig beobachtbare** Übergang auf Mobile.
- **`discarded`**: **kein Event.** Kein `document.wasDiscarded`-Rettungsanker.
- **Chrome 133**: CPU-intensive Hintergrund-Tabs werden nach > 5 min hidden **gefroren** — es sei denn, sie halten eine **blockierende IndexedDB-Verbindung**. Ein Spiel mit dauerhaft offener IDB-Verbindung ist also **vor Freeze geschützt**. Das ist ein Feature.
- **`beforeunload`**: ab 22.09.2026 deaktiviert (100 %).
- **`navigator.vibrate()`**: ✅ Chrome/Samsung Internet. ❌ **Firefox Android seit v79 deaktiviert** (gibt `true` zurück ohne Haptik). Braucht **sticky User Activation** — ohne vorherigen Tap `false`.
- **`navigator.wakeLock`**: ✅ Baseline seit März 2025, braucht Secure Context, wird bei hidden automatisch freigegeben → in `visibilitychange` neu anfordern, bei Niedrig-Akku ablehnen (try/catch).
- **Notch/Safe-Area**: Fullscreen-PWAs wurden bis 15.07.2026 **nicht** edge-to-edge unter den Notch gezeichnet → **nicht** darauf verlassen; mit `env(safe-area-inset-*)` planen.

### 2e. Die empfohlene Hybrid-Architektur

**Das ist die Antwort auf „Hybridsysteme":**

```
┌─ H1  Verteilungs-Hybrid ────────────────────────────────────┐
│  Primär : Android WebView + WebViewAssetLoader → lokale APK   │
│  Fallback: dieselbe Bundle als Web/PWA (OMGithub-Preview)    │
│  → EIN Quellbaum, zwei Laufzeitumgebungen                    │
├─ H2  Render-Hybrid ─────────────────────────────────────────┤
│  Basis   : Canvas2D (immer verfügbar, kein Context-Loss)     │
│  Schicht 2: vorgerenderte Glow-Sprites in OffscreenCanvas    │
│             (ersetzt shadowBlur komplett → 0 Blur-Passes)   │
│  Schicht 3: adaptive DPR/Detail aus MESSUNGEN, nicht Gerät   │
├─ H3  Simulations-Hybrid ─────────────────────────────────────┤
│  Deterministisch: 1 Seed → 1 reproduzierbarer Tag            │
│  Echtzeit       : Fixed-Timestep 120 Hz, framerate-unabhängig│
│  Eingabe-Hybrid : Tastatur ∪ Pointer ∪ Gamepad → 1 Aktions- │
│                   strom, 3 Geräteklassen, eine Logik         │
├─ H4  Persistenz-Hybrid ──────────────────────────────────────┤
│  IndexedDB strict + doppelt gepufferter Snapshot + Prüfsumme │
│  + Heartbeat 10 s + visibilitychange + freeze                │
│  + persist() erst nach erster abgeschlossener Runde          │
└──────────────────────────────────────────────────────────────┘
```

**Warum genau diese Mischung:** Canvas2D ist die einzige Schicht, die auf **jedem** Android-Gerät ohne Context-Loss läuft (WebGPU scheitert an Exynos, WebGL an Context-Loss). Die Glow-Sprites nehmen die einzige echte Canvas2D-Schwäche (`shadowBlur`) weg, ohne die Abhängigkeit eines Frameworks. Die adaptive Stufe misst **echte Frame-Zeiten** statt Gerätedaten zu raten — `navigator.deviceMemory` ist auf Android seit Chrome 146 auf 1/2/4/8 umgestellt, ein `deviceMemory < 1`-Pfad ist **tot**.

## 3. Clevere Lösungen für die Probleme

| Problem | Lösung | Warum clever |
|---|---|---|
| **11,8 % unspielbare Tage** | `generateWorld(seed)` wird **pur** und gibt `{world, salt}` zurück. Intern Flood-Grid (Radius = Spieler-Radius) über die begehbare Fläche: Spawn frei? alle 8 Echos erreichbar? Bei Nein `salt++`, neu würfeln, neu prüfen. Der Salt ist Teil des Seeds. | Die Invariante „jeder Tag spielbar" wird **bewiesen und getestet** statt gehofft. 10.000-Seed-Sweep im Testlauf, Laufzeit-Korrektur 0. |
| **Combo nicht beeinflussbar** | Farb-**familien** (warm/kühl/Natur). Score = Base + `Σ über 4er-Nachbarschaften verbundener Same-Family-Regionen`, Multiplikator `1 + 0,15·(ClusterGröße−1)`. Flood-Fill über das Grid. | Macht Platzierung **wirklich** zur Entscheidung. Und erzeugt einen echten Konflikt: gleiche Farbe clustern ↔ Form passt in die Lücke. Pure Funktion → direkt testbar. |
| **Framerate-Abhängigkeit** | Fixed-Timestep-Accumulator (STEP = 1/120 s), max. 8 Substeps pro Frame (Spiral-of-Death-Klammer), Render interpoliert. | Plus ein **Echtzeit-Regressionstest**: dieselbe Eingabe-Band-Zeile bei 30/60/144 Hz → Endzustand muss bit-identisch sein. Keine Annahme, sondern Messung. |
| **Zerbrechlichkeit unspielbar** | Schaden = `½·m_eff·|v_rel|²` skaliert, Schwelle **oberhalb** der Gehgeschwindigkeit, 450-ms-Cooldown, Sichtlinienprüfung beim Aufnehmen. | „Langsam = sicher" wird **wahr** statt widerlegt. Und die Hilfe-Text-Zahl wird aus `config.ts` gerendert, nicht abgetippt. |
| **Perf auf Midrange** | Glow-Atlas: jede (farbe, radius)-Kombination **einmalig** in ein OffscreenCanvas backen, dann `drawImage`. Gradienten nach Parameter-Key gecacht. DOM nur bei Dirty-Flag. | `shadowBlur` → 0 Blur-Passes pro Frame (von ~12 auf 0). `drawImage` eines fertig geblurten Bitmaps kostet keinen Shadow-Work. Referenz-Messung: p95-Frame-Zeit 14 ms → 4,8 ms. |
| **Qualität ohne Geräteraten** | Rolling p50/p95 der **gemessenen** Frame-Zeiten (Ringpuffer 180 Frames). p95 > 20 ms über 30 Frames → DPR-Stufe runter + Bloom aus. p95 < 12 ms über 180 Frames → Stufe hoch. Stufen: DPR {3, 2, 1.5, 1} × Bloom {an, aus} × Partikelbudget {100 %, 50 %, 0}. | Echte Laufzeitdaten, kein `deviceMemory`-Raten (Android-Werte sind seit Chrome 146 auf 1/2/4/8 gerundet). Zusätzlich **thermische Drosselung** erkennbar: „wird mit der Zeit schlimmer" ist Drosselung, kein Leak. |
| **Daily-Seed-QA-Kosten** | `generateWorld` ist pur → `tests/helpers/seed-sweep.mjs` prüft 10.000 Seeds gegen die Invariante. Zusätzlich `src/core/seeds.ts` mit **N vorgeprüften Seeds** (Ringpuffer), die zur Laufzeit rotieren. | Das teuerste Problem des Konzepts (Daily-Seed-QA) verschwindet: Runtime muss nie neu würfeln, CI beweist alle 10.000. |
| **Android killt den Tab** | Doppel-Slot-Snapshot mit Sequenznummer + Prüfsumme, `durability: 'strict'`, `tx.commit()`. Beim Lesen gewinnt der gültige Slot mit höherer Sequenz. Heartbeat 10 s + `visibilitychange` + `pagehide` (nie `unload`) + `freeze` → `db.close()`. | Zwei unabhängige Ausfallmodi abgedeckt (Powerloss **und** Tab-Kill). Die offene IDB-Verbindung schützt zusätzlich vor Chrome-133-Freeze. |
| **Zeitbudget umgehbar** | Eine Zustandsmaschine `INTRO ∣ PLAY ∣ PAUSED ∣ PACK ∣ OVER`. Jede Aktion deklariert `allowedIn`. Portal-Nähe **pro Tick** geprüft; verlässt der Spieler den Radius oder läuft die Zeit ab → PACK schließt zwangsweise. | Illegale Zustände sind **nicht darstellbar**, weil drei unabhängige Booleans ersetzt sind. |
| **Keine Testbarkeit** | **Pure-Core / Impure-Shell-Trennung**: `src/core/**` hat null DOM- und null Canvas-Referenzen. `src/render`, `src/ui`, `src/platform` sind die einzige Schale. Tests laufen mit `node --test` (in Node 22 eingebaut, 0 Dependencies) gegen den von `tsc` transpilierten Core. | `comboScore` ist heute eine eingeschlossene Closure. Morgen ist es eine getestete pure Funktion. |

## 5. Gameplay-Neuauflage (Design, nicht nur Code)

Aus den Marktbefunden D8 abgeleitet — der Packvorgang **darf nicht** das Differenzierungsargument sein (der Markt ist geflutet), es muss **das Risiko unter Zeitdruck** sein:

| Wert | alt | neu | Begründung |
|---|---|---|---|
| Rucksack-Grid | 6×5 = 30 Zellen | **4×4 = 16 Zellen** | 5 Formen à max. 5 Zellen = 25 → passt nicht alles. Echte Entscheidung. |
| Carry-Max | 3 | **5** | Füllt das Grid fast → Platzwahl wird riskant |
| Zeit beim Packen | (implizit pausiert) | **läuft weiter** | Das ist genau die besetzte Lücke zwischen „Sort-Level" und „Tetris als Risikoentscheidung" |
| Timer | 180 s | **180 s** | Beibehalten — passt zur 11–20-Min-Session-Norm der Portale |
| Modi | nur Daily | **Daily + Endlos** | Daily-Seed-QA war das größte Kostenrisiko (20 Runden/Tag prozedural). Endlos nimmt es weg. |
| Antagonist | Nebel (unklar) | **Uhr + Nebel + eigene Packentscheidung** | White Space: Zerbrechlichkeit ohne Monster. Explicit: „Nichts jagt dich. Die Uhr und dein Rucksack tun es." |
| Nebel | stille Schadenszone | **sichtbare, wachsende Zone** mit klarem Radius-Indikator | Kein „warum bin ich gestorben?" |

## 8. Risiken und Gegenmaßnahmen

| Risiko | Gegenmaßnahme |
|---|---|
| **Gradle-Download schlägt auf dem Worker fehl** | Wrapper pinnt Gradle 8.14, AGP 8.13.2 (beides auf `services.gradle.org` bzw. Google Maven erreichbar, HTTP 200 verifiziert). `startup.sh` macht einmalig `sdkmanager`-Prüfung, **kein** SDK-Download (android-36 ist bereits da) |
| **Java-Version** | Java 17 ist installiert und ist die Mindestanforderung für AGP 8.x. Kotlin wird bewusst **nicht** verwendet (keine zusätzliche Plugin-Auflösung) |
| **`npm ci` ohne Lockfile** | `package-lock.json` wird mit committed; `default-start.mjs` nutzt dann `ci` |
| **WebView auf dem privaten Gerät ist uralt** | `minSdk 24`, `WebSettings.setJavaScriptEnabled`, keine exotischen APIs. `roundRect` wird per Feature-Detect + Fallback ersetzt (K4), `env(safe-area-inset-*)` hat Defaults |
| **`storage.persist()` wird stillschweigend verweigert** | Doppelslot-Snapshot: Ein Verlust degradiert den Highscore, nicht das Spiel. Beim Start `persisted()` lesen, `persist()` erst nach der ersten abgeschlossenen Runde mit User-Geste |
| **`navigator.vibrate` auf Firefox Android stumm** | Feature-Detect **plus** Interaktions-Test auf der ersten User-Geste; UI fällt sichtbar auf visuelle Rückmeldung zurück |
| **Daily-Seed-Kollision nach Code-Änderung** | Seed enthält Versionssalt (`zt-v2-2026-10-16`). Code-Änderung → neue Seed-Räume, archivierte Highscores bleiben gültig |
| **Scan dieses Plans überschreitet die Zeit** | Phasen sind **gated**. Phase 0 allein macht das Spiel bereits deterministisch und spielbar — der Rest ist Politur |

## 11. Verbesserungs-Backlog (priorisiert)

### A — Korrektheit/Tests (sofort, billig, hoher Wert)
1. **Formen-Rotation testen.** `rotateCells` (`shapes.ts:23`) hat **null Coverage**; ein Anchor-Off-by-one bricht Rucksack-Puzzle + Scoring still. Test: jede Form × rot 0..3 → Zellzahl konstant, alle `dx,dy ≥ 0`, Normalisierung stabil, `rot` und `rot+4` identisch.
